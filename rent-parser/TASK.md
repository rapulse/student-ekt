## 3. Архитектурные решения и обоснования

### 3.1. Изоляция и чистота системы: почему локальный `package.json` и отдельный Google Chrome
- **Вопрос пользователя:**  
  *«Ставим puppeteer-core в проект? Получается не в проект, а в глобальный node? Или мы здесь ветку node создадим? ... Запуск Яндекс Браузера с отладкой — то есть мне нужно закрыть браузер и открыть с отладкой? Это и будет защита от неприятностей? Или лучше поставить полный Chrome пакет как параллельный браузер и использовать его для разработки?»*
- **Принятое решение:**
  1. **Google Chrome установлен параллельно** через Homebrew (`brew install --cask google-chrome`) специально под задачи разработки и парсинга. Это изолирует личные сессии, пароли и вкладки в Яндекс Браузере.
  2. Зависимости Node.js установлены **локально** в папку `rent-parser/package.json` (`puppeteer-core`). Глобальный `npm` остаётся чистым.

### 3.2. Градация сложности парсинга
1. **Быстрый уровень (Python HTTP stdlib):**  
   Для ресурсов без жестких WAF-блокировок: Яндекс Недвижимость, Яндекс Аренда, Telegram, ВКонтакте. Отрабатывает за 10–15 секунд без открытия окон.
2. **Браузерный уровень (Google Chrome + puppeteer-core):**  
   Для Авито и Домклик, защищённых системами анализа цифровых отпечатков (Qrator, Kasada, WAF).  
   - Флаги: `--disable-blink-features=AutomationControlled`, удаление `navigator.webdriver`.
   - Постоянный профиль `chrome_profile/` для сохранения cookies и сессий.
   - Если сайт выдаёт интерактивную капчу — пользователь решает её в видимом окне один раз (Human-in-the-loop).

### 3.3. Формат данных Parquet — максимальный сбор без потерь
- **Довод:** Нельзя срезать поля на этапе сбора.
- **Реализация:**  
  - Нормализованные типизированные поля: `id`, `source`, `source_type`, `url`, `title`, `price`, `deposit`, `commission`, `rooms`, `area`, `floor`, `address`, `lat`, `lon`, `first_seen`, `last_seen`.
  - Поле **`raw_json`**: сохраняет полный оригинальный ответ сервера / текст карточки / все свойства без сжатия и урезания.
  - Файл хранится в `data/listings.parquet` и сжимается через snappy.

### 3.4. Принцип «Собирать всё — фильтровать при просмотре»
- Собирается вся база города без жесткого отсечения по полигону кампуса на этапе сбора.
- Все фильтры (Полигон кампуса НВК, Зоны 1–5, ⭐ Только Яндекс Аренда, по комнатам и цене) применяются в визуализаторе [map.html](../map.html).

### 3.5. UX: Сценарий запуска
Единая точка входа — скрипт `run.sh`:
- `./rent-parser/run.sh` — полный цикл: быстрые сборщики + Chrome для Авито и Домклика + обновление Parquet + обновление карты `map.html`.
- `./rent-parser/run.sh --fast` — экспресс-прогон без браузера (15 секунд).

## 4. Ревизия и доработка (11.10.2026, вечер)

### Найденные ошибки первой версии (исправлены)
- Залог Яндекс Аренды принудительно ставился 0, хотя `rentDeposit` бывает (35 000, 27 000) → теперь берётся как есть, у Аренды с залогом пометка «уточнить».
- `agentFee` Яндекса — это **проценты**, а писался в рубли → `commission_pct` + `commission_rub` отдельно.
- КУ читались из пустого `utilitiesFee` → учитывается и `utilitiesIncluded`.
- Тип квартиры читался из несуществующего `category` (верно — `offerCategory`), студии без `roomsTotal` → `house.studio`.
- Неизвестное подставлялось как «0» (Домклик «без комиссии», Авито-Аренда «без залога») → теперь `None` и «❓ уточнить».
- Собиралась 1-я страница Яндекс Аренды (20 из 131), 2–4 страницы Авито/Домклика → полный проход + инкрементальный режим.
- Дубли между сайтами не сверялись → `pipeline/dedup.py` (дом + комнаты + этаж + площадь ±2 м²; посты — по тексту).
- `map.html` monitor/ перезаписывался → rent-parser пишет **`map_all.html`**.
- Пропавшие объявления не отмечались, цена перезаписывалась → `is_active`/`inactive_since` (только после полного прохода), `price_history`/`prev_price`.
- Вывод Node перехватывался — пользователь не видел просьбу решить капчу → stdio наследуется, `ensureContent()` спрашивает в терминале.

### Решения пользователя
- **Полный проход нужен один раз**, дальше — только новое: выдачи отсортированы по дате, листаем, пока на странице есть новые ID (`--full` — принудительно, например раз в неделю, чтобы отметить пропавшие).
- **Авито: один парсер общей выдачи**, без отдельного сценария для Яндекс Аренды. Аренда опознаётся в той же выдаче по продавцу «Яндекс Аренда» или тексту описания (в описаниях латиница вместо кириллицы: «Яндeкc Аpeндoй» — нормализуется).
  - Профиль Яндекс Аренды на Авито адресов не показывает; поиск `q=яндекс аренда` показывает 47, но парсер листал подмешанные «ещё объявления» (840) — отказались.
- **Карточки Авито по одной не открываем** (4 тыс. — долго и риск блокировки). Всё, кроме координат, есть в выдаче; координаты — геокодер. Карточка открывается только: у компактных карточек без адреса (до 40 за прогон) и у отмеченных «интересно» в просмотрщике.
- Фильтр пользователя на Авито (`f=…` = студия/1к/2к + «Проверены в Росреестре») **отсекал Яндекс Аренду и 3к** → собираем всю выдачу (~4300), отметка Росреестра хранится и фильтруется в просмотрщике.
- Важные отметки сохраняются в `badges`: «Проверено в Росреестре», «Собственник», «Документы проверены», «Реквизиты проверены», «Данные подтверждены», продавец (Домклик / агентство / собственник), «N завершённых объявлений».

### Где что лежит
| Файл | Что делает |
|---|---|
| `config.py` | точка НВК, полигон, зоны, бюджет (как в monitor/) |

# rent-parser — шпаргалка

Сбор аренды по всему Екатеринбургу → `data/listings.parquet` → просмотрщик **`map_all.html`**.
Подробности, ошибки первой версии и решения — в `TASK.md` (раздел 4).

## Что запускать (из папки `student_nvk`)

| Когда | Команда | Сколько идёт | Что делает |
|---|---|---|---|
| **Каждый день** | `./rent-parser/run.sh` | ~10–15 мин, откроется Chrome | только новое: каждый поиск листается по дате, пока на странице есть новые объявления |
| Быстро, без браузера | `./rent-parser/run.sh --fast` | ~1–2 мин | только Яндекс + ВК/Telegram |
| **Раз в неделю** | `./rent-parser/run.sh --full` | ~1 час, Chrome | все страницы всех источников: снятые объявления → «пропало», изменения цен у старых |
| Если остались адреса без координат | `./rent-parser/run.sh --geocode-only` | ~4 с на дом | догеокодировать всё сразу |
| Посмотреть результат | `open map_all.html` | — | карта OpenStreetMap + список + фильтры |
| …то же на Яндекс Картах (основной) | `open map_yandex.html` | — | метки «цена с КУ 👥», кнопка «на весь экран», кластеры, пробки, «Как добраться» |

Во время прогона с Chrome окно открывается само. Если сайт покажет капчу, в терминале появится
«🧩 … реши её в окне Chrome» → решить в окне → Enter (или `s` — пропустить источник). Окно закрывается само.

## Почему ежедневно не нужен полный проход
Все выдачи отсортированы по дате публикации, новые объявления — сверху. Обычный прогон
листает страницу за страницей и **останавливается на первой странице без новых ID**
(это надёжнее, чем «за сутки»: если пропустить день, догонит сам). Лимит — 10 страниц
(500 объявлений Авито), с запасом на сутки.

Чего обычный прогон не видит — то делает `--full` раз в неделю:
- **снятые объявления** («пропало» в просмотрщике; без полного прохода нельзя отличить «снято» от «не долистали»);
- **изменение цены у старых объявлений** (история цен, «подешевело»).

| Авито (вся выдача, по дате) | avito.ru/ekaterinburg/kvartiry/sdam/na_dlitelnyy_srok-ASgBAgICAkSSA8gQ8AeQUg?localPriority=0&s=104 | 4348 |
| Домклик (по дате публикации) | ekaterinburg.domclick.ru/search?deal_type=rent&category=living&offer_type=flat&sort=published&sort_dir=desc | 1207 |
| Telegram | t.me/s/ekatarenda | 127 постов |
| ВК | m.vk.com/ekb_arenda, rent_flats, podselenieeburg | 461 пост |

Ссылки одни и те же для `--full` и для ежедневного прогона — разница только в том, сколько страниц листать.

Почему именно так:
- **Авито `s=104`** = сортировка «по дате». Фильтр «Проверены в Росреестре» в ссылку **не** ставим: он отсекал
  всю Яндекс Аренду (у неё нет этой отметки) и 3к. Отметка сохраняется — фильтр есть в просмотрщике.
- **Яндекс Аренда на Авито** отдельно не собирается: она приходит в общей выдаче и опознаётся по продавцу
  «Яндекс Аренда» или шаблону описания («…на N этаже в N-этажном доме на срок от 11 месяцев»).
- **Домклик `sort=published`, а не `sort=updated`**: агентства раз в сутки перевыгружают фиды, и сотни старых
  объявлений одновременно получают новую «дату обновления» — новые тонут среди них. `aids=20561` — это сам
  Екатеринбург, количество то же (1201), поэтому не нужен.

## Координаты
- Яндекс, Домклик — координаты с сайта (точно).
- Авито — по адресу: сначала тот же дом с Яндекса/Домклика («координаты: дом с другого сайта»), иначе
  геокодер OpenStreetMap / Nominatim («координаты: геокодер», точность до дома). Уходит только адрес дома.
- Кэш `data/geocache.json`: каждый дом спрашивается один раз. Лимит обычного прогона — 100 запросов
  (~7 мин), улицы зон НВК — первыми. Новых домов за сутки обычно десятки, так что после разового
  `--geocode-only` координаты есть почти у всех сразу.
- Подстраховка — геокодер Яндекса (≤900 запросов/сутки, только для домов, которых нет в OSM). Сейчас **выключен**:
  ключ не принят (403). Включить: добавить `"yandex_geocoder": "<ключ HTTP Геокодера>"` в `rent-parser/local_keys.json`
  и запустить `./rent-parser/run.sh --geocode-only`.
- Дом не найден нигде → точка по улице («≈ точка по улице, дом не найден»).
- Без координат объявление всё равно есть в списке: фильтр «Где → всё, и без координат», поиск по улице.

## Время в пути (оценка): НВК, старый корпус РТФ, фитнес
- Отдельный скрипт `rent-parser/transit/transit.py`: базу только читает, пишет `data/transit.json` по точке дома
  (одна точка — один расчёт, сколько бы там ни было квартир и сайтов). `run.sh` запускает его после сбора
  и пересобирает карту; если он упал — база и карта остаются как были.
- Куда и с каким весом — `DESTS` в начале скрипта: НВК 6, старый корпус РТФ (Мира, 32) 1, фитнес 1 (корпус и фитнес обычно в один день)
  (фитнес — ≈ Фурманова / 8 Марта, по скриншоту; уточнить адрес). Среднее по весам идёт в «⭐ Топ».
- Все маршруты города (автобус, троллейбус, трамвай, метро) с порядком остановок — из OpenStreetMap
  (Overpass, без ключа), кэш `data/transit_routes.json`, обновляется раз в неделю (`--refresh` — сразу).
  Если в OSM одно направление маршрута нет или оно недорисовано — берём другое наоборот.
- Кратчайший путь с пересадками (Дейкстра): пешком до остановки (по прямой ×1,3, 4,5 км/ч) + ожидание на каждой
  посадке 7 мин (метро 4) + езда (автобус 20 км/ч, трамвай 17, метро 40) + пересадки пешком до 400 м + пешком до цели.
  Без расписаний и пробок.
- Ключ Яндекс JS API маршруты не строит (`429 limited`, проверено 12.10.2026).
- Разбор одной точки: `python3 rent-parser/transit/transit.py --check 56.8121,60.631`.

## Умный фильтр «⭐ Топ» (эксперимент)
- Отдельный скрипт `rent-parser/smart/smart.py` → `data/smart.json`: уровень надёжности (A — Я.Аренда, B — собственник/проверки,
  C — без проверок, ⚠ — похоже на приманку: цена <75% медианы типа в зоне + нет номера дома / агентство без проверок),
  минимальный срок (метка «срок от N мес» или текст), баллы (параллельный вариант для сравнения).
- «Рынок» (в каждой карточке): медиана цены с КУ того же типа у соседей — наименьший радиус из 1,5 / 2,5 / 4 / 7 км,
  где набралось ≥10 разных квартир (дубли с разных сайтов — один раз), иначе по городу. КУ — как на карте (в т.ч. оценка).
  Зелёный — дешевле на 15%+, красный — дороже на 15%+, серый — в пределах ±15%.
- В просмотрщике: «⭐ Топ» — 30 лучших после остальных фильтров: без приманок, ≤30 000 ₽/чел в мес, дорога ≤45 мин,
  без мин. срока от 6 мес (кроме Аренды). Порядок — уровень, затем «₽/чел в мес, если жить N мес»
  (залог и комиссия — как потерянные, неизвестные — по худшему: залог = месяц, комиссия 50%) + 100 ₽ за минуту дороги.
- Отложено (12.10.2026, сравнение: топ-30 совпадает на 20–22 из 30, баллы тянут вверх «без залога, но дороже»):
  баллы не учитывают «живу 3/8 мес» и считают цену ступеньками; можно разделить B на «квартира + личность»
  (Росреестр/документы + СберID/Госуслуги) и остальное — скидкой в ₽, а не отдельной ступенью.
- Удалить целиком: папку `rent-parser/smart`, `data/smart.json`, блок «УМНЫЙ ФИЛЬТР» в `viewer_template.html`, строку в `run.sh`.

## Просмотрщик map_all.html / map_yandex.html
Оба файла собираются каждым прогоном из одного шаблона, отличается только карта. Цвета: ⭐ Яндекс Аренда — фиолетовый,
Яндекс — красный, Домклик — зелёный, Авито — синий, ТГ+ВК — жёлтый.

- **Источники** — 5 переключателей (можно несколько): ⭐ Яндекс Аренда (её сайт + Аренда на Авито),
  Яндекс Недвижимость, Домклик, Авито, ТГ + ВК. Цифра — сколько активных объявлений.
- **Одна квартира — одна карточка**: если квартира есть на нескольких сайтах, внутри все объявления
  по приоритету (Аренда → Яндекс → Домклик → Авито → посты), у каждого — цена, въезд, ID (клик копирует),
  продавец, дата, ссылка. Крупная цена — самая низкая с КУ, но не у объявления, где «комиссия ?», если
  другой сайт пишет «комиссия 50%»; такие расхождения — оранжевым тегом «комиссия 50% (Яндекс)».
- **Тип**: студия / 1к / 2к / 3к / 4к+ / комната (у постов — угадан по тексту).
- **Важно** (нужно всё выбранное сразу): 👥 Можно вдвоём, Проверено в Росреестре, Документы проверены, Реквизиты проверены,
  Личность подтверждена (Авито «Данные подтверждены», Домклик СберID/Госуслуги), Собственник,
  Без залога, Без комиссии, КУ включены. «Без залога/комиссии» не пропустит квартиру, если хоть один сайт
  пишет обратное.
- Ниже: где (зоны + Аренда до 7 км / полигон / весь город / и без координат), до ₽/мес с КУ, км, в бюджете,
  новые за сутки/3 дня/неделю, отметки, сортировка (цена с КУ, въезд, ближе, новые, подешевели, на нескольких сайтах),
  + снятые, поиск по улице/ID/тексту. Фильтры запоминаются; «Сбросить фильтры» — вверху.
- Яндекс-карта: метки «цена с КУ 👥 ✓» цветом источника; кластер «55 · от 14к» (количество и минимальная цена).
  Клик по кластеру: если квартиры в одном доме — список слева показывает только их (плашка «📍 в этом доме … ✕»),
  иначе карта приближается. Кнопка ⤢ — карта на весь экран.
- Карта: цвет точки — лучший источник квартиры, зелёное кольцо — «интересно»; клик по точке — к карточке,
  клик по заголовку карточки — к точке.
- «Интересно» / «Отказ» / заметка — на всю квартиру (все её объявления). **«Выгрузить отметки»** →
  `~/Downloads/nvk-marks.json` → следующий прогон заберёт их в базу и для «интересных» объявлений Авито
  откроет карточку (дозагрузит подробности).
- **Цена** — крупно сумма в месяц **с КУ**, под ней как на сайте: «аренда 20 000 + КУ ~4 000 (оценка)»,
  «аренда 20 000 + ЖКУ 3 000 + счётчики ~1 500 (оценка)» или зелёным «КУ 0 — включены».
  Оценка КУ, если сайт не дал сумму: 2к+ ~6 000, 1к/студия ~4 000, комната ~2 000.
- **Въезд** — отдельной строкой: «Въезд 50 000 ₽ = аренда 20 000 + залог 20 000 + комиссия 10 000 (50%)»;
  залог оранжевым, комиссия красным, «без залога / без комиссии» зелёным, «?» — сайт не указал (сумма «+?»).
- **👥 вдвоём — по N ₽** (зелёный) — можно делить аренду: 2к и больше, или 1к от 35 м², если в тексте
  «евродвушка / кухня-гостиная». Нет, если в тексте «только одному». Иначе серый «👤 на одного».
- **В бюджете**: одному — до 30 000 ₽/мес с КУ, вдвоём (👥) — до 60 000.
- Посты ВК/TG старше 60 дней считаются неактуальными (видны с «+ снятые»).
- **«Новое»** = добавлено в базу после первого сбора 11.10 (первый сбор — база, он «новым» не считается).
  Метка «новое · 12.10» — 2 дня. Фильтр «Новые»: **с прошлого прогона** (то, что принёс последний run.sh),
  за сутки / 2 дня / неделю — с количеством в скобках. Журнал прогонов — `data/runs.json`.
  Удобно после ежедневного run.sh: «Новые → с прошлого прогона» + сортировка «цена с КУ».

## Файлы
- `data/listings.parquet` — вся база (поле `raw_json` — исходные данные сайта без потерь).
- `data/geocache.json` — кэш координат.
- `data/transit.json`, `data/transit_routes.json` — время в пути (оценка) и маршруты OSM.
- `rent-parser/local_keys.json` — ключ Яндекс Карт JS API (не в git; ключ виден внутри map_yandex.html — файл никуда не выкладывать).
- `rent-parser/tmp/` — временные файлы прогонов (можно удалять).
- `_tmp/` — архив старого `monitor/` (первая версия проекта).
